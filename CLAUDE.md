# The Epoch Institute — Site

Multi-page historical research site. Static files, no build step.

## Pages
Root pages are **extensionless** files served as HTML by `.htaccess` (`ForceType`):
index · research · research-series · about · contributors · dataset · explorer · profiles · community · today-in-history
Plus 404.html and generator.html (generator is NOT deployed — see .cpanel.yml).

empire/* — 94 extensionless empire pages (empire/.htaccess forces text/html), generated by generator.html
logos/<Empire Name>.png — empire emblems, used by profiles, explorer and empire pages
data/history.json, data/international-days.json — Today in History data (built by scripts/)

## Shared files
- /shared.css — all CSS
- /shared-nav.js — initNav(activePage), escHtml(), jsonp(), buildPagination(), isValidEmail(), share buttons
- /shared-data.js — core data loaded on every page: API URLs, EMPIRES (94), EMPIRE_INFO, REGIONS, ERAS, EVENTS, TRANSLATIONS, toSlug()
- /point-descs.js — POINT_DESCS, loaded only by explorer
- /empire-profiles.js — EMPIRE_PROFILES, loaded only by profiles and generator.html
- /epoch-stats.js — radar-chart stats, loaded by profiles and empire pages

Script tags carry a `?v=N` cache-buster (JS is cached for 1 month by .htaccess).
When you change a shared .js file, bump its `?v=` on every page that loads it,
including the template in generator.html and the 94 empire pages.

## Key variables (shared-data.js)
EPOCH_API_URL — Google Apps Script (articles, opinions, announcements, confirmed_articles)
FORMSPREE_URL — contact + newsletter forms
CONTRIB_URL — separate Apps Script for contributors

## Deployment
Push to master → GitHub Actions (.github/workflows/deploy.yml) tells cPanel to pull and run .cpanel.yml,
which copies files to /home/theeiorh/public_html/. Manual fallback: cPanel → Git Version Control → Deploy HEAD Commit.
New top-level files must match a copy rule in .cpanel.yml (*.js, *.css, *.json, etc.) or they won't be deployed.

## Encyclopedia
- `encyclopedia` page (top-level nav item): index view, and one article per entry at `/encyclopedia#<slug>`.
- `encyclopedia-data.js` — 3,736 entries (slug, name, type, aka, dates, desc, img, credit, empires). Generated.
- `encyclopedia-links.js` — regex patterns used to find entry names in text. Loaded by `generator.html`
  (gold `.enc-link` links on empire pages: first mention per section, never the empire's own name) and by
  the encyclopedia page (links inside descriptions).
- `images/encyclopedia/<slug>.jpg` — freely licensed Wikimedia Commons thumbnails; author/licence/source
  are in each entry's `credit` and shown under the image. Keep the credit if an image is reused.

## Kinds of profile (not only empires)
The Institute profiles states and empires today and will add cultures, ideologies, movements and more.
`PROFILE_KINDS` in shared-data.js defines each kind: label, URL folder (`path`), section scheme, and whether it has a
power curve (`chart`: explorer, radar stats, related empires). Helpers: `profileKind(e)`, `profileSubtype(e)`,
`profileUrl(e)`. EMPIRES entries without `kind` are polities (URL /empire/<slug>, unchanged).
To add a new profile, e.g. a culture:
1. Add `{name, region, kind:'culture', start, end}` to EMPIRES (`points` only for polities) and a one-line teaser to
   EMPIRE_INFO.
2. Add its texts to EMPIRE_PROFILES using that kind's section keys (e.g. origins, society, beliefs, arts, exchange,
   legacy) plus summary and references.
3. Add an .htaccess ForceType rule for the new folder (copy empire/.htaccess) and a copy rule in .cpanel.yml.
4. Regenerate pages (generator.html), rebuild the encyclopedia links (they match entry names in all profile texts),
   regenerate home-data.js / search-index.js. The profiles page shows a kind filter once a second kind exists.

## Homepage and site search
- `home-data.js` — HOME_PICS (one distinctive picture per empire for the featured cards), HOME_ENTRIES
  (encyclopedia "entry of the day"), HOME_COUNTS. Loaded only by `index`.
- `search-index.js` — SEARCH_INDEX [slug, name, type, aliases] for the header search (shared-nav.js
  `initSiteSearch`; loaded on first open; "/" or Ctrl+K opens it). Bump `search-index.js?v=` in shared-nav.js
  when regenerated.
- Both are generated from encyclopedia-data.js + empire-section-images.js; regenerate them whenever those change.

## Empire pages
- `empire-section-images.js` — SECTION_IMAGES: one picture per profile section (an encyclopedia entry linked in
  that section, with its image and credit). Loaded only by generator.html; rendered as `.profile-section-fig`.
- `empire-facts.js` — EMPIRE_FACTS: capital, founder, predecessor, successor per empire (key-facts box).
  Loaded only by generator.html. The template also builds the table of contents, reading time and
  related/earlier/later empires from EMPIRES (same region, overlapping years).
- `profile-changes.md` — log of the Oct 2026 fact-check of all 94 profiles (corrections per empire). Not deployed.
- Editing profile text can break encyclopedia matching: entries are found by their exact name or aliases, so keep
  full names (e.g. "the Battle of Mohács", not "at Mohács") or the entry loses its link.

generator.html must produce output identical to the committed empire/* files — edit the template
there rather than editing the 94 pages by hand. To regenerate: open generator.html from a local
server, download empire-pages.zip, extract into empire/, commit and push.

## Encyclopedia previews
`data/enc-preview/<first char>.json` hold preview cards (name, type, dates, two sentences, image) for gold links; shared-nav.js `initEncPreviews` fetches them on hover/focus/first tap. Regenerate after rebuilding encyclopedia-data.js (scratchpad design2/make-previews.ps1 logic: first two sentences, max 280 chars).
